# R393〜R401 — 音声の立ち上げ（R392 ベース）

スピーカーから音を出すための、UEFI での試験の記録。R400 で起動時のテスト音が鳴った。R401 は、そのテスト音を初期設定で止めた版。

## 音の経路

メモリ → ADMA チャンネル 0 → ADMAIF1 → AHUB の XBAR → I2S（0x702D1000、DAP1、Tegra がマスター）→ ALC5639（I2C1 の 0x1C、スレーブ）→ スピーカー

- コーデックの動作クロックは、I2S の BCLK を元に、コーデックの PLL1 で作る。
- 48 kHz、16 ビット、ステレオ。テスト音は 1 kHz のサイン波。

## 各版でわかったこと

- **R393 / R394:** コーデックが応答するのを確かめた（ID2 = 0x6231）。PZ4（LDO1_EN）を入れてから 400 ms 待つ必要がある。
- **R395:** 最初の APE のレジスタを読んだところで止まった。
- **R396:** d_audio のクロック（CLK_OUT_ENB_V bit 10、ソースは clk_m）を入れ、APE のリセットを外した。これでレジスタに触れるようになった。
- **R397:**
  - コーデックの I2C は I2cLib を使う。I2cLib は I2C1 をパケットモードから外したままにするので、BM92T の読み出しが失敗していた。音の処理のあとでパケットモードに戻す。
  - ADMAIF と I2S に、Linux と同じ初期値を書く。
- **R398:** CPU から ADMAIF の FIFO に書いても進まなかった。Linux と同じく ADMA で送るようにし、ADMAIF まではデータが届いた。
- **R399:** Linux と同じく、I2S の受け側をソフトリセットするようにした。ところが、このリセットが終わらなかった。
- **R400:**
  - **原因:** 0x702D1000 の I2S のクロックは、CAR の **i2s0**（L bit 30、ソース 0x1D8）だった。Linux のデバイスツリーで確かめた。
  - R395〜R399 が入れていた CAR の i2s1（L bit 11、0x100）は、隣の 0x702D1100 の I2S 用だった。
  - 直したところ、リセットがすぐ終わり、テスト音が鳴った（2026-11-01、ユーザー報告。音量はかなり大きい）。
- **R401:** 起動のたびに 1 秒鳴るテスト音を、初期設定で止めた。
  - `UsbPowerAudit.c` の `SWITCH_AUDIO_TEST_TONE` を 1 にしてビルドすれば、また鳴る。
  - コーデックの確認（R393）と、I2C1 をパケットモードに戻す処理（R397）は、今までどおり動く。

## 成果物

- ROM: `D:\Codex\coreboot-R401.rom`（各自でビルドする。ROM は配らない）
- SHA-256: `dfef1c1de96fe2349787c0d2735e8bdab9ff25a3ef9592307d74b5773ef25f91`
- `EDK_SOURCE_RESTORE_MATCH=YES`
- R401 は、テスト音を止めた状態では実機でまだ試していない。

## まだできていないこと

- Windows の音声ドライバ。
- 音量の調整、ヘッドホン、マイク。

## もし起動しなくなったら

R392 の ROM で起動すれば、元に戻る。
